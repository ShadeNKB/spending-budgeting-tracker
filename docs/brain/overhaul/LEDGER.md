## Lead decisions

- Lint rule `jsx-a11y/no-autofocus` is off. `autoFocus` is only used inside dialogs the user opens, which follows the WAI-ARIA dialog pattern. The real focus bugs are fixed in T6.
- Unit-test timezone runs on Windows must use PowerShell `$env:TZ`. Git Bash does not honour IANA TZ names, which caused one false "all green" during T0. Reviewers caught it.
- **PR-0 merge model: whole-record last-writer-wins.** Three review rounds showed that rescuing concurrent edits of different fields of one record on the v4 wire (a pending-edit rebase with acknowledge and confirm cycles) kept producing new failure modes, the last a premature acknowledgement and an endless push loop. The v4 wire has no per-field versions; v5 merges per field. PR-0 therefore ships v0.8.4's semantics for concurrent edits, made deterministic and convergent, plus every fix that stops real loss.
- **PR-0 main chunk +4.9 KB**, over the spec §17.3 line of +3 KB. Accepted: CI's budget still passes (684.7 / 700 KB), and the overage is the honest-status UX and the per-key mapping stamps. The framer-motion → CSS swap wins far more back.
- **`mappingUpdatedAt`**, a new additive top-level v4 wire field, accepted. v0.8.4 drops it, which only re-creates deterministic ties. PR-2 entry criterion: the v5 wire reads, writes or passes it through, and PR-1's frozen v0.8.5 model is reconciled with the merged PR-0.
- **PR-0 residual risk, accepted: a mixed-version delayed sync.** A 480-seed soak (fresh seeds) passed 400 / 400 two-device seeds and 79 / 80 seeds next to a 0.8.4 device, in Asia/Singapore and Pacific/Kiritimati. In the failing seed (90058) the old device's push and the new device's push cross within a fraction of a second; the new device's lands last without the old device's new entry (no compare-and-set on the v4 wire), and the old device drops the realtime event that would make it push again (its own F-002). The entry is not lost: it stays on the old device and syncs at the next change on either device, or when that device updates. A fix (absorbing news-event payloads into the next merge) would only matter during the rollout window, so it was not added to the release unreviewed; v5's compare-and-set removes lost updates altogether.
- **T5b, AC-F1 not met by either build, accepted.** The target of a p95 frame interval of at most 20 ms holds only for the swipe in headless Chromium at 4× CPU. The overlay scenarios sit at 33–67 ms on 0.9.3 and on T5b alike, so this is the runner, not a regression; every scenario's INP proxy and longest frame improved.
- **T5b changes `modalLayer.ts`, accepted.** The page scroll lock now lasts until a closed sheet or the palette has left the page (`holdScrollLock`), not just until it closes: WebKit ends a running CSS transition when the body's overflow changes, so unlocking at the close skipped the slide out on iPhone.
- **T5b's surviving test mutants, accepted.** Four of 47 survive the unit tests (a reopen passing through `starting`, the FLIP measuring a leaving toast, the timing of the toast-left press guard, the sheet waiting on its panel only). The lead checked the press-guard one by hand: moving `noteToastLeft` to the moment of dismiss turns "notes its spot for the trash beneath only once it has left the page" red, so that guard is pinned.
- **Routed from T5b's review** (all present on 0.9.3, outside its scope): a fast double Enter in the palette after opening it with Search on iPhone (T7); axe target-size on a ledger row partly under the sticky day header when scrolled deep (T7); new and edited entries are stored as UTC ISO strings, not the documented local-noon form (PR-2 checks what reads them; only zones at UTC+12 and beyond could see a different day).
- **Release tags only on a verified merge commit.** Check that the PR state is `MERGED` and that `origin/main` equals the merge commit before tagging (see Incidents).
